**Date:** 2026-10-24

### Added

- **Шифрование протокола (MSE/PE)**, как в qBittorrent, µTorrent и Transmission. Пиры, которые требуют шифрование, не принимали Kino совсем: с ними теперь можно соединиться. Такие пиры частые на русских трекерах — шифрование там советуют против замедления провайдером. Поэтому на одной и той же раздаче Kino находил меньше пиров, чем qBittorrent.
  - Настройки → Загрузки → Соединение → «Шифрование»:
    - «Предпочитать» (по умолчанию): сначала шифрованное соединение, с пиром, который не умеет, — обычное;
    - «Требовать»: только шифрованные, остальные пиры не подключаются;
    - «Отключить»: только обычные.
  - Применяется после перезапуска Kino, как и остальные параметры соединения.
  - Работает для TCP и µTP, для исходящих и входящих соединений.
  - В librqbit (движок торрентов Kino) шифрования нет и в последней версии 9.0.1. Поэтому Kino держит у себя его копию с добавленным шифрованием: `apps/desktop/src-tauri/crates/librqbit`, подключена через `[patch.crates-io]`. Отличия от исходника описаны в её `KINO.md` и помечены `// Kino:` в коде.
  - Реализация по спецификации Vuze/Azureus:
    - обмен ключами Диффи — Хеллмана по 768-битному модулю;
    - RC4 с ключами из общего секрета и хеша торрента, первые 1024 байта отбрасываются;
    - входящая сторона находит торрент по `HASH('req2', SKEY)`;
    - поддерживается начальная нагрузка (BitTorrent-рукопожатие внутри шифрованного), обычное входящее рукопожатие распознаётся по первым байтам.
- **Постоянный порт для входящих.** Раньше он был случайным при каждом запуске. Теперь порт выбирается при первом запуске (свободный, из диапазона 20000–40000) и сохраняется в настройках, поэтому его можно один раз пробросить на роутере. Если в поле порта поставить 0, при следующем запуске выберется новый. В автономном режиме тестов порт не выбирается.
  - Подсказка к порту в настройках: «Выбран при первом запуске и больше не меняется — его можно пробросить на роутере. 0 — новый при следующем запуске».
- Скрипт `apps/desktop/scripts/libtorrent-peer.py`: пир на libtorrent (движок qBittorrent) с принудительным шифрованием RC4, для проверки совместимости.

### Changed

- В копии librqbit убран `sqlx` (функция `postgres`, Kino её не использует). Иначе его sqlite конфликтует с rusqlite Kino, когда копия входит в рабочее пространство Cargo (а входит она для того, чтобы запускались её тесты).

### Tests

- Найдено проверками и исправлено до выпуска:
  - режим шифрования доходил до сессии, но не до соединений уже добавленного торрента: торрент строит их параметры сам. Теперь режим передаётся в торрент (`ManagedTorrentOptions::peer_encryption`);
  - шифрованный µTP с libtorrent вставал сразу после рукопожатия. Читатель µTP сдвигает переданные ему буферы, поэтому расшифровывались не те байты. Теперь читателю передаются отдельные представления буферов, на это есть регрессионный тест.
- Rust — 128 и 2 пропущенных по умолчанию. Новые:
  - два движка Kino договариваются о шифровании: «требовать» ← «предпочитать», «требовать» ← «требовать» и «отключить» ← «предпочитать» качают; «требовать» ← «отключить» не соединяются;
  - порт выбирается один раз и сохраняется;
  - `encryption_interop_with_libtorrent` (пропущен по умолчанию, нужен Python с libtorrent): libtorrent 2.1.1 с принудительным RC4 раздаёт — Kino «Предпочитать» скачивает; Kino «Требовать» раздаёт — libtorrent скачивает. Пройден по TCP, по µTP и с обоими протоколами.
- Шифрование в копии librqbit (`cargo test -p librqbit mse`) — 8:
  - векторы RC4;
  - общий секрет Диффи — Хеллмана;
  - шифрованное соединение в обе стороны, с записью по байту и 100 КБ данных;
  - рукопожатие как начальная нагрузка целиком в первом чтении;
  - предложено обычное и разрешено;
  - обычное рукопожатие в каждом режиме;
  - отказ, когда шифрование отключено или торрент чужой;
  - читатель, сдвигающий буферы.
- clippy без замечаний.
- Vitest — 97 + 204, новое: переключатель «Шифрование» в настройках.
- E2E — полный прогон, 41 сценарий, все прошли.
