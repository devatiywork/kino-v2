**Date:** 2026-10-24

### Added

Этап 6 ТЗ: установщик и Kino как часть Windows.

- **Установщик** (`bun run --filter @kino/desktop build` → `Kino_<версия>_x64-setup.exe`, NSIS):
  - ставится для текущего пользователя, без прав администратора, на русском;
  - libmpv лежит рядом с программой. Её кладёт хук установщика, а не `bundle.resources` Tauri: ресурсы Tauri копирует в `target\debug` при каждой отладочной сборке — поверх DLL, занятой запущенным dev-Kino, и сборка падала;
  - ассоциации файлов: видео (mkv, mp4, m4v, avi, mov, webm, wmv, flv, m2ts, mts, mpg, mpeg, vob, ogv, 3gp) и `.torrent`;
  - схема `magnet:`;
  - Kino в «Приложениях по умолчанию» Windows (Capabilities + RegisteredApplications, хук `windows/hooks.nsh`). Удаление убирает это.
  - `.ts` в ассоциации не входит: это ещё и TypeScript, Kino не перехватывает его у редактора. В «Приложениях по умолчанию» `.ts` есть — выбрать Kino можно вручную.
- **Одно окно** (ТЗ 6 «Система»): второй запуск Kino — двойной клик по видео, `.torrent` или magnet-ссылке, ярлык — передаёт файл уже запущенному Kino и сразу выходит. Окно Kino выходит вперёд, в том числе из трея и из свёрнутого состояния, а файл открывается: видео — в плеере, торрент — в окне добавления.
  - Один Kino на папку данных: именованный мьютекс и сообщение `WM_COPYDATA` скрытому окну. Kino автотестов и отладочная сборка со своей папкой данных никогда не встретятся с Kino пользователя.
  - Выключателя нет: два Kino на одной базе и одних торрентах сломали бы друг друга.
- **Медиаклавиши** (ТЗ 6 «Система», по умолчанию включены):
  - Kino — медиасеанс Windows (System Media Transport Controls): пауза, следующая и предыдущая серия с клавиатуры и из медиапанели Windows, даже когда Kino не на переднем плане;
  - в медиапанели — сериал и «S01E05 · имя файла»;
  - «следующая» и «предыдущая» доступны, только если такие серии есть;
  - «Стоп» ставит на паузу;
  - сеанс включён, только пока открыто видео; выключатель срабатывает сразу.
- **Программы по умолчанию** — Windows не даёт программе назначить себя самой, поэтому настройки показывают, что выбрано сейчас, и ведут на страницу Windows с выбором:
  - «Открывать видео через Kino» (раздел «Система»);
  - «Kino как обработчик .torrent и magnet:» («Загрузки» → «Поведение»).
  - Строка показывает, чем открываются видео, `.torrent` и magnet-ссылки сейчас («Kino», «qBittorrent», «программа не выбрана»). Кнопка «Выбрать в Windows…» открывает «Приложения по умолчанию» на странице Kino. Вернувшись в Kino, строка читает выбор заново.
- Ядро:
  - `instance.rs`, `media_keys.rs`, `defaults.rs`;
  - событие `app://open`;
  - настройка `mediaKeys`;
  - путь к данным вычисляется до запуска Tauri;
  - относительные пути из командной строки берутся от папки запуска.

### Changed

- Переменные автотестов (`KINO_TEST_OFFLINE`, `KINO_TEST_VOLUME`, `KINO_TEST_MONITOR`) работают и в релизной сборке, чтобы проверять её без запроса брандмауэра. При `KINO_TEST_OFFLINE` нет ни трея, ни медиасеанса.
- Мок Tauri в Vitest знает текущее окно: можно тестировать код, который вызывает `getCurrentWindow()`.

### Not in this version
