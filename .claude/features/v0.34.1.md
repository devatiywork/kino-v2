**Date:** 2026-11-15

### Fixed

- **Kino перестал запускаться после перезагрузки Windows.** Окно не появлялось, процесс сразу завершался.
  - Причина. Порт DHT (UDP) движок librqbit в первый раз берёт случайный, из динамических портов Windows (49152–65535), и навсегда запоминает в `torrents\engine\dht.json`. Hyper-V, WSL и Docker при каждой загрузке резервируют в этом диапазоне куски портов, каждый раз другие. У владельца DHT жил на порту 58672, а после перезагрузки Windows зарезервировала диапазон 58672–58771. Движок получал отказ (WSAEACCES, 10013), запасной запуск «с настройками по умолчанию» брал тот же `dht.json` и падал так же, а ошибка движка торрентов останавливала запуск всего приложения.
  - Порт DHT теперь выбирает Kino, по тому же правилу, что и порт для входящих: из 20000–40000, ниже динамических портов. Сохранённый порт остаётся, только если он вне динамического диапазона и Windows его даёт (проверка UDP на IPv4 и IPv6). Иначе берётся свободный порт из диапазона Kino, а таблица узлов DHT сохраняется. Порт для входящих не берётся: его по UDP занимает µTP. Если в диапазоне ничего не свободно, на этот запуск берётся случайный порт.
  - Запуск движка теперь в три попытки: настройки → настройки по умолчанию → без DHT. Даже если порт снова откажет, Kino запустится, а торренты будут работать через трекеры и PeX. Сами настройки в журнал не пишутся: в адресе прокси может быть пароль.
  - Код: `torrent/engine.rs` (`dht_port`, `stored_dht_port`, `udp_free`, `DhtSessionConfig.port`), `torrent/mod.rs` (`engine_tries`, общий `seed()`).
