**Date:** 2026-10-24

### Added

- **Сохранение паролей сайтов в окне трекеров** — встроенный менеджер паролей WebView2, по умолчанию включён:
  - после входа на сайт браузер показывает своё окно «Сохранить пароль?» с логином, «Сохранить» и «Не сейчас»; в следующий раз подставляет логин и пароль в форму;
  - пароли хранит WebView2 в папке данных Kino, зашифрованными Windows для учётной записи пользователя; сам Kino их не видит и не читает;
  - «Загрузки» → «Поведение» → «Сохранять пароли сайтов» — выключатель срабатывает сразу, без перезапуска;
  - «Сохранённые пароли» → «Удалить…» (с подтверждением) удаляет пароли и данные форм всех сайтов окна трекеров. Вход, в котором вы сейчас, остаётся. Удалить можно, даже если вкладку «Трекеры» ещё не открывали: профиль WebView2 общий у главного окна и браузера трекеров;
  - зачем: RuTracker часто завершает сессию, и с сохранённым паролем повторный вход — один клик. Kino сам вход не теряет: cookies сайтов переживают перезапуск.
- Ядро:
  - `trackers/autofill.rs` (`ICoreWebView2Settings4.IsPasswordAutosaveEnabled`, `ICoreWebView2Profile2.ClearBrowsingData`);
  - настройка `savePasswords`;
  - команды `tracker_password_saving`, `tracker_clear_passwords`.

### Checked by hand

- На локальной тестовой странице входа (тестовый логин и пароль): после отправки формы WebView2 показал окно «Сохранить пароль?» с этим логином.
- Страница входа RuTracker сейчас закрыта проверкой Cloudflare «Один момент…»; Kino её не обходит. Поэтому, почему RuTracker завершает сессию, со стороны сайта не проверено.

### Tests

- Vitest — 94 + 184: сохранение включено по умолчанию, выключение уходит в ядро; удаление — только после подтверждения, с сообщением.
- E2E — 36: настоящий WebView2 трекеров предлагает сохранять пароли, переключатель меняет это сразу; удаление паролей не сбрасывает вход на сайт.
