### Added

- **Spike `spikes/tauri-mpv`**: проверка главного риска архитектуры. Можно ли показывать видео libmpv внутри окна Tauri, а интерфейс рисовать поверх видео? **Да**, запасной вариант с внешним `mpv.exe` не нужен. Подробности и снимки — в `spikes/tauri-mpv/README.md`
  - рецепт: непрозрачное окно + прозрачный фон WebView2 (`backgroundColor: #00000000`) + своё дочернее окно для видео внизу z-порядка без `WS_CLIPSIBLINGS`, libmpv рисует в него через `wid`
  - не работает: `transparent: true` (видео пропадает, сквозь окно виден рабочий стол) и `WS_CLIPSIBLINGS` у окна видео (WebView2 вырезает его область)
  - проверено на настоящей серии 720p: аппаратное декодирование d3d11va, `gpu-next`, 0 потерянных кадров; озвучка переключается за 2 мс без перезагрузки видео; субтитры mpv; видео в части окна; скрыть и показать видео; полный экран, развернуть, свернуть; клики и перетаскивание окна идут в страницу; перетаскивание файла в окно
  - нагрузка в debug-сборке: около 17% одного ядра вместе с WebView2, 179 МБ
  - ограничения для дизайна: `backdrop-filter` не размывает видео; субтитры mpv надо поднимать, когда видна панель управления
- `scripts/fetch-libmpv.ps1` — скачивает libmpv (shinchiro/mpv-winbuild-cmake) в `vendor/libmpv` и делает из экспортов `libmpv-2.dll` библиотеку импорта `mpv.lib` для MSVC
- `.cargo/config.toml` — больше повторов при скачивании крейтов, без HTTP/2-мультиплексирования: crates.io на этой сети иногда обрывает TLS-рукопожатие
